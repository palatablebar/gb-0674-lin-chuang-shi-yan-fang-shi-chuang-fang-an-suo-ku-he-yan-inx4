# 访视与冻结定义

样例均为虚构编号，无身份信息。受试者入组日期由subjects表唯一确定，记录中的入组基准必须完全一致。采样日期和入组日期均转为Asia/Shanghai日历日期，差值为访视日；时刻先统一UTC。
方案选择按当前受试者assignment和该次发生时刻查半开生效窗，匹配必须唯一，不能使用全局最新方案。v1访视V1=[5,10)、V2=[12,17)；v2为[6,11)、[13,18)。受试者00001于10月10日转v2，其他受试者仍用v1。
PRIMARY计入访视完成，RETEST只替代该次测量值。首次记录必须唯一且在访视窗内。缺首次访视、重复首次和窗外访视均阻断，复检不能填补漏访或消除原偏离。
复检须引用同受试者同访视的PRIMARY，晚于原采样且不超过72小时，版本必须更高。同最高版本复检冲突时保留原结果并阻断。所有检验值以mg/dL输出，g/L乘100。

## 首次采样冲突采信（原始优先，唯一结论）

CSV支持可选第12列`source`，取值`ORIGINAL`（原始采血）或`BACKFILL`（补录）；缺列或留空默认`ORIGINAL`，其他值隔离为`BAD_SOURCE`。同一受试者+访视出现多条PRIMARY且含补录时，采信策略固定为：

- 恰有一条ORIGINAL：该条记`record_role=OFFICIAL_ORIGINAL`作为正式首次记录，所有BACKFILL隔离为`BACKFILL_SUPERSEDED`，隔离明细保留原值、行号与所指向的正式记录号。
- 只有BACKFILL、无ORIGINAL：全部隔离为`BACKFILL_NO_ORIGINAL`，该访视按缺首次访视（`MISSING_PRIMARY`）阻断，补录不得充当正式记录。
- 多条ORIGINAL互相冲突：整组隔离为`ORIGINAL_CONFLICT`待人工核查，不产生正式记录。

补录覆盖首采会把窗外访视漂白为窗内，因此方案选版、访视排窗、偏离、复检裁决与锁库闸门只读取正式首次记录，四个模块与采信页共用同一结论。无`source`列的历史文件不触发本裁决，重复首次仍由偏离模块`DUPLICATE_PRIMARY`处理。

## 冲突包追溯与上游失效

每批按受试者-访视-类型-记录号身份计算`lineage_key`（冲突包身份）。同输入重跑批号与采信结果不变，不新增采信记录；同冲突包出现新批号（上游更新）时，旧批自动置`已失效`并以`superseded_by`指向新批，新批`manifest.replaces`回指旧批，对失效批次的复核提交返回409 `SUPERSEDED_RUN`。不同冲突包互不影响。锁库页逐项列出来源类别、原因码、记录号与明细，未采信来源均可在采信页与冻结包`evidence.json`追溯。

锁库须所有规定访视完成，无偏离、复检问题和隔离行。冻结包包含每条选定结果、原始行号、方案版本与访视窗。此工具只验证试验数据完整性，不做诊断判断或生产锁库。
